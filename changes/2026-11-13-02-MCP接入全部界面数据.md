# MCP接入全部界面数据与按需刷新

## 改动原因

用户要求把界面已经展示的内容全部集成进 MCP。此前仅支持落盘快照、历史指标和 CPU/内存排行，缺少硬件详情与出站流量。

## 改动内容

- 保留 get_snapshot/get_history，新增 refresh_dashboard、get_hardware_details、get_realtime、get_traffic，共 6 个工具。
- 覆盖型号/硬件清单、CPU逻辑处理器、GPU全部明细与限制、内存条/内存用量/时序、物理磁盘SMART明细、网卡/IP/网关/DNS、主板分组、显示器分辨率/刷新率/色域、主题和历史保留天数。
- 出站查询支持本次、今天、滚动7天、自定义闭区间，公网/局域网/其他/总量排序与分页，返回程序完整路径和名称。本次包含当前速率、状态和丢失标记；历史说明覆盖范围不能代表连续采集。
- MCP通过同一用户会话的命名事件通知现有后台按需刷新，不启动另一个遥测进程，不切换UI、不自动提权。默认刷新不启用流量；start_traffic=true 明确开启本次持续采集。
- 后台只在有限刷新窗口导出 dashboard.json，通过临时文件原子替换；保留1秒/5秒采样与5秒历史写入规则。仅在该窗口保留CPU/GPU详情采样基线，避免逐项读取相互重置。
- 返回生成时间、各节采样时间/age_ms、真实传感器状态。非有限读数转换为JSON null，实测零仍为0，GPU限制不可用时不伪报false。SMART/时序可复用既有约60秒缓存，静态清单缓存与UI一致。
- 更新设置页MCP说明、MCP.md和README，忽略Python缓存目录，补充Python单元测试、原生JSON测试和真实stdio验收脚本。

## 实际验证结果

- 根目录 ./build.ps1 构建成功，输出 build/ComputerWatch.exe；./install.ps1 更新成功。
- 安装可执行文件与构建产物SHA256一致；安装MCP脚本与源码SHA256一致。
- 使用项目固定的 mcp==1.29.0 运行 tests/test_mcp.py，7项测试全部通过：工具发现/参数枚举校验、分页/排序/闭区间、空记录、缺失/零、损坏缓存/旧数据库、默认刷新不启动流量、显式开启、旧快照/历史接口兼容。
- tests/mcp_export_tests.cpp 编译运行成功，Python解析导出JSON验证中文、换行、引号、反斜线、零/null、健康false和缺失限制状态。
- 对 C:/Program Files/ComputerWatch/mcp_server.py 建立真实MCP stdio连接，完成初始化、6个工具发现、全部详情section和4种流量时间范围调用；非法排序参数被拒绝。
- 实机刷新读到32个逻辑处理器且32项负载有效、2块磁盘（SMART明细分别30/29行）、6个网卡、2台显示器、6个主板分组；出站状态0、丢失0，本次15个程序，历史汇总174个程序（均为测试时点读数）。
- 内存时序如实返回backend_missing及PawnIO IntelMCHBAR/Broadwell-EP适配原因，不当作可用读数。CPU封装温度71°C/功耗约7.18W，GPU温度51°C/板卡功耗41.8W，为本机MCP返回值，未做外部工具对照。
- 仪表盘与助手任务均Running，权限分别Limited/Highest，没有修改登录触发器。

## 待验证与限制

- Windows窗口截图报 window capture timed out；重试不含截图的可访问性读取成功，点击CPU详情报 coordinate input geometry is unavailable。因此无法完成实时→CPU详情→返回的实际操作回归，也不能宣称完成视觉验收；此次界面仅修改设置页一句说明。
- MCP 1.29.0 的依赖输出lifespan前向引用警告，但7项测试和真实stdio全部成功，未改动现有固定版本。
- 详情是显式刷新的缓存，后台退出后仍可读；调用者必须检查时间戳。刷新结束并不意味着所有传感器可用。历史出站数据无每时刻丢失标记，不能补算未启用期间。
- 尚未跨Windows登录会话实测，也未做长时间资源开销测试；现有配置不变，客户端需重启MCP服务发现新增工具。
